# Security model

This prototype is local, **mock by default**, and hardware-untested; its only non-mock path is the operator-only, opt-in, subscribe-only X2D LAN observation described below. Report software issues through this repository without attaching credentials, device serials, access codes, network addresses or camera images. No private vulnerability-reporting service is assumed to be configured.

## Enforced boundaries

- Only stdio is served. There is no HTTP listener, remote endpoint, network discovery, FTP/video client or cloud account integration. The sole network client is the opt-in X2D read-only MQTT subscriber below.
- No tool accepts an address, device credential, file path, URL, G-code, shell command or raw printer command. Strict input schemas reject extra fields.
- Controls and camera are disabled by default. Mock startup flags enable simulations only. `--enable-x2d-lan-readonly` is the one flag that would open a real connection, and only for passive telemetry; that is behavior after contract admission, which is currently closed, so today it refuses before any input is read or connection exists.
- A finite action enum and fixed synthetic artifact allowlist constrain control requests. Prepared actions bind printer, job, action and state revision; expiration, replay and state checks apply again at execution.
- Unknown firmware and invalid/missing state fail closed for actions. Missing data is never replaced by an invented safe temperature or progress reading.
- Camera output is a synthetic placeholder and separately gated. No camera URL or credentials are returned.
- MCP errors use bounded application messages; no raw transport exception is sent to the client. Server diagnostics use stderr.
- Dependencies are locked. Installs disable lifecycle scripts. CI has read-only repository permissions and does not persist checkout credentials. No printer or cloud secrets are used by tests.
- The Docker runtime uses the unprivileged `node` user with root-owned application files and production dependencies. The documented run command disables networking, writes, Linux capabilities and privilege escalation, mounts no host data/devices/socket, and limits CPU, RAM and processes. These runtime flags are operator configuration; the image alone cannot enforce them.

## X2D LAN read-only observation (operator-only, opt-in)

- Disabled unless the operator passes `--enable-x2d-lan-readonly` (or runs `npm run smoke:x2d-readonly`), and **currently unreachable**: `LanReadOnlySession` throws `CONTRACT_UNVERIFIED` at construction while the report topic, MQTT version, subscription QoS or installed X2D firmware/schema lacks vendor-verified evidence in the frozen ledger. No acknowledgement, flag, environment variable, option or injected seam substitutes for evidence; the old acknowledgement string was removed. Admission is a code-path invariant (a pure rule over a frozen ledger), not a privilege boundary: anyone who can modify the source can change it. The engine behind the wrapper is imported by nothing else under `src/` (a test enforces this) and exists only for offline tests.
- Inputs (private IPv4 literal, serial, access code) are ephemeral: inherited environment variables (removed from the environment after reading) or one stdin JSON line. They are never arguments, tool inputs, log text, files or Git content. The access code is sent only after TLS verification succeeds, as the MQTT password. Erasure is limited: the code necessarily exists as JavaScript strings (environment, stdin line, session configuration) and inside the encoded CONNECT packet, whose copies are not all zeroed, so this project does not claim complete erasure of the secret from process memory. An inherited environment variable is visible to the same OS user (and to whatever launched the process) while it runs; prefer stdin, and never put these values in an MCP host's configuration file.
- TLS: only the supplied CA roots are trusted (default: the vendor public CA shipped with Studio); system roots are not added, chain and exact serial hostname are checked, and no TLS-relaxation option exists, on fixed port 8883. Certificate failure closes without retry and before any credential is sent.
- The MQTT codec can encode only CONNECT, one literal SUBSCRIBE (no wildcards), PINGREQ and DISCONNECT; there is no PUBLISH or acknowledgement encoder, outbound frames are type-branded, and a runtime gate writes only a buffer that is exactly one frame of a permitted type (it verifies type, flags, length and trailing bytes, not minimal remaining-length encoding or every packet body), counting and refusing anything else. Tests assert zero outbound PUBLISH, including a permitted prefix followed by a PUBLISH.
- Retained reports are historical and age-unknown: counted but never parsed or shown as telemetry, and they cannot refresh age. Status is withheld until a live (non-retained) frame arrives.
- The CA file is operator-supplied trust (the vendor CA is not fingerprint-pinned; the default is the public certificate in the installed Studio app). It is read by a bounded regular-file reader: single non-blocking, no-follow open, `fstat` regular-file check on the descriptor, byte-capped read. FIFOs, devices, directories and growing files are refused and cannot hang the process; errors are fixed labels without the path.
- Peer content is untrusted: size-capped, strictly parsed and reduced to a whitelist; raw payloads, topics, errors and certificates are never forwarded. Failure messages are fixed text. Stale data is withheld.
- Limits: ≤60 s, 20 messages and 1 MiB for the smoke launcher; library defaults are larger but finite. Deadlines and frame age use the larger of the wall-clock and monotonic elapsed deltas. Closing stdin releases the live session. No automatic reconnect. Unknown nozzle mapping reports no nozzle readings (an empty `nozzlesC`).
- Residual risk: the report topic, MQTT version, QoS, X2D firmware and schema are unverified implementation choices. A reachable device holding the correct vendor-signed certificate for that serial and the access code is trusted as the data source; its readings are observations, not safety information.

## Trust limits

The local user and MCP host can launch and invoke this process. Stdio relies on operating-system process isolation; this server does not authenticate an identity. Any client allowed to use an opted-in simulator can submit `confirmed: true`. Plan identifiers are workflow references, not credentials or human-consent tokens. A malicious host can modify its local source or call tools repeatedly. Tool annotations are hints and are not authorization controls.

Simulated state checks are not a physical safety system. No emergency stop, thermal protection, collision detection, material compatibility or machine interlock is implemented. Never attach a real transport to these tools merely because a test passes.

## Before any hardware adapter

Require separate owner authorization and exact model/firmware/network-mode evidence. Start with read-only telemetry. Keep device secrets in an OS secret store or untracked local configuration and redact them from prompts, logs, exports and tests. Use verified encrypted/authenticated transport; do not disable certificate validation. Restrict destinations and payloads to a reviewed device allowlist. Keep authorization, privacy permissions, command acknowledgement, timeout/uncertain outcome handling and freshness separate from telemetry parsing.

A future physical command needs an independently trusted approval path bound to the exact target, job/artifact, action and expiry. An LLM's own confirmation is insufficient. Recheck state immediately before dispatch, deduplicate requests, never retry an uncertain physical action automatically, and retain safe local operator control. Do not enable Developer Mode or accept vendor acknowledgements automatically. Laser, cutting, plotting, settings, heating, motion and firmware operations remain outside scope.
