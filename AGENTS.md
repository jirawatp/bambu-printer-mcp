## Scope and safety

- Agents and automated tests must not discover/connect to any printer, open any network connection, perform any hardware action, real print/job/firmware command, cloud login or credential configuration is authorized. Test only in-memory synthetic fixtures. The simulator's confirmation boolean is not hardware authorization.
- Scoped authorization (X2D read-only observation): any live read-only observation of a supported X2D is performed by the project owner/operator alone, with ephemeral in-memory input, through the opt-in `--enable-x2d-lan-readonly` path or `npm run smoke:x2d-readonly` (see docs/hardware-validation.md). That path is currently admission-blocked and has no override. Agents must still never read or print access codes, tokens, device addresses or serials, or any vendor-app private configuration; never connect, scan or discover; never operate a device UI; and never add a publish/control/camera path, persist credentials, change printer or vendor-app settings or accept a vendor plugin/license. Print, pause, cancel, heat, move, calibrate, settings, firmware and camera actions remain unauthorized. All agent-run tests stay offline against in-memory fakes. Commit, push and a pull request for this repository are authorized after the independent Opus review; merge and deploy remain unauthorized. Mock tests and observation output never establish firmware, schema or hardware compatibility.
- The live path is admission-blocked: `LanReadOnlySession` refuses construction until `src/lan-contract.ts` holds vendor-verified evidence for the report topic, MQTT version, subscription QoS and installed firmware/schema. Never add an acknowledgement, flag, environment variable or option that opens it, and never label an implementation choice as verified.
- Keep default-deny simulator controls and camera access, exact mock-firmware contracts, job/revision-bound expiring one-use plans, finite artifact allowlists and unknown telemetry semantics. No arbitrary commands/files/URLs/G-code.
- No public endpoints, persistent access, new credentials, purchases, agreements, publication or merge. Push and pull requests only as authorized above, never merge or deploy. This repository only: do not modify other projects, global tool configuration or MCP client configuration. Never print secrets.
- Preserve private/UNLICENSED publication guards and pending owner license decision. Mock tests never establish hardware compatibility. Do not widen the X2D observation transport (no publish, control, camera, discovery, retry or relaxed TLS) as a way to "finish" this prototype.
- Reproducible setup is `npm ci --ignore-scripts`. Keep stdout MCP-only, errors bounded and secret-free. Docker is the intended restricted runtime; do not start an engine or alter settings automatically. Preserve existing nonroot/read-only/network-disabled CI checks.
